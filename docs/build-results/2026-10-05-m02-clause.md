# M02.1 固定 ReadClause 切片验收 — 2026-10-05

纯 JS ReadClause 状态机、固定标点属性和独立 C 参考已完成本轮实现与差分验证。**639 个输入中，598 个完整读至 EOF 并逐字段匹配 C，41 个报告已登记的依赖缺口；共比较 1341 次完整 clause 返回。** 集成 Node 测试 **128/128、0 skip**。此结果为 `passed-supported-slice / coverageComplete:false`，不是完整 M02 或 TTS 完成。

## 实现与边界

- [ReadClause](../../src/core/read-clause.js)：固定 en-us / UTF-8 / C-string / 800 字节逻辑容量，独立会话状态；保留 source bytes、int16 charix、tone/terminator、回退读取和跨调用计数。接口、分配与来源见 [READ_CLAUSE](../READ_CLAUSE.md)。
- [标点原语](../../src/core/clause-type.js)：原 `clause_type_from_codepoint` switch；原始 top12 Unicode property 由固定 C 数据导出，128 个稀疏区间 / 1536 字节 TypedArray。未把 C 最终 clause 答案序列化为运行期表，见 [CLAUSE_TYPE](../CLAUSE_TYPE.md)。
- [独立 C oracle](../../tools/oracle/clause.mjs)：分别链接原 clean/instrumented 库，实际初始化导出 profile，直接调用原函数；不改上游、M01 helper、baseline 或稳定 trace 补丁，见 [ORACLE_CLAUSE](../ORACLE_CLAUSE.md)。
- [差分入口](../../tools/compare/clause.mjs)：比较完整 sourceHex、charix、charixTop、tone、terminator、voiceChangeHex、startCharacter、前后状态；不读取预期状态回填 JS。连续调用依据返回的 CLAUSE_TYPE_EOF，不能仅检查 decoderEof。

固定 profile 来自原 C 初始化：phonemeInput=256、endPause=4096、numbers=16779328、dictCondition=72、phonemeTable=80，countCharacters 从 -1 开始。首次 `stateBefore.phonemesRepeatCount=null` 表示 C 未初始化该字段，进入函数后及后续的实际整数逐项比较。

ReadClause 自身的多次直接调用没有下游 tokenizer/词翻译器的状态变更，**不声明完整 TranslateClause 多句集成**，不生成 startWord。

## 差分与例外处理

默认 seed **1592639746（0x5eedc102）**；128 组随机文本和 128 组原始字节。另含原22 smoke、标点/缩写/日期/数字、CRLF与段落、BOM/NUL、混合脚本/emoji/ZWJ、全部256首字节、725/796附近容量及多字节越界窗口、phoneme括号和多clause。

|---|---:|

| 只比较上限内前缀、未到 EOF | 0 |
| `punctuation-name-dictionary` 明确拒绝 | 11 |
| `embedded-command` 明确拒绝 | 30 |
| 已比较完整 clause 返回（包括例外前正确前缀） | 1341 |

原 `Wait... what?` 保留为明确缺口，未从语料删除。除 U+2026 外，上游把 U+0EAF、U+1801、U+FE19、U+22EE..U+22F1 也作为 ellipsis；本轮补入全部这些分支。所有上述字典分支仍未实现，不能用返回空串或硬编码读名假装完成。

[clause-exceptions.json](../../tools/compare/clause-exceptions.json) 锁定每条例外的 case ID、输入 SHA256、reason、codepoint 和 clauseIndex；其余样例必须完整匹配，不能把曾经支持的随机样例降格为“不支持”。即使是登记例外，也必须先比较正确前缀、校验触发码点/原始输入的必要证据、错误状态及会话失效后的稳定行为。该输入证据只检查必要条件，不复制 ReadClause 上下文算法。

新增 seed 或语料若碰到未登记的不支持分支，检查会失败，需审查实际源码与输入后维护清单；基础设施错误、C 进程失败、schema/状态差异始终失败。实现真正补齐已登记依赖后，也须先核对 C 差分再删除对应例外，不能自动改变验收口径。

审查发现并修复了比较器原先对 fuzz 使用宽泛不支持原因名单的问题；负例验证普通文本伪报“不支持”、错码点、错误状态、丢字段/多字段、提前 EOF 与输入截断都不能通过。核心本轮未发现 C/JS 行为差异。
