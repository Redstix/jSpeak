# Runtime profile and device gate

执行范围与阶段见 [最终实施计划](DEVELOPMENT_PLAN.md)。本文规定运行时隔离、数据/音频缓冲和真机验收；尚未填写的产品预算不得当成已通过。

## 当前事实

目标 Redmi Watch 5，432×514、designWidth 432；设备 API 返回 `ap / 0.0.0 / API1200`。用户已于 2026-10-14 明确告知该目标使用 **QuickJS** 运行 Xiaomi Vela JS 应用；真实固件版本、QuickJS 版本和具体平台行为仍未核实。六轮证据见 [STATUS](STATUS.md) 与 `docs/device-results/`。

- 被测 TypedArray、DataView、Math.imul 和 32-bit shift 语义通过，计算 hash 跨端一致。
- 16000Hz 包内预置 WAV 已确认出声；JS 生成双音 WAV 经 internal 写入、全字节读回、系统播放后，用户也确认出声。22050Hz参考语音的包内和46424B完整文件两路也经用户听感确认；0.4.1修正视图缓冲后，append/position与头回填均46424B全字节一致、播放及清理成功，用户确认清晰完整一致，见[第六轮](device-results/2026-10-05-probe-0.4.1.md)。
- `.txt` 名真实phondata 600104B全读、32KiB扫描、高偏移/跨页/末尾及EOF已证；898009B候选整读驻留和组装驻留通过；`.bin/.dat/.wav` 包内读取被拒，包内源 copy/access 路线关闭。
- 核心兼容目标为固定 Oracle 的 **PCM16 / mono / 22050Hz**；22050Hz固定短句真机播放已确认，当前无需重采样。完整 WAV 文件是已选设备出口，项目不依赖原始 PCM 播放 API。
- M11 Node 有界命令→PCM运行时已验收：170命令、4096样本/块、最多4块在途（32768B）、100次会话无状态串扰。完整文本→PCM与Vela文件播放仍未集成。
- 当前候选装载已证；完整reader初始化、最终驻留预算、合成 RTF、峰值 heap、文件间隙及稳定性尚未证实。assemble共19764ms，maxHashCopy685ms待调查；应用可见backing峰值930777B不是heap。双音 534ms/2s 不是 eSpeak DSP 基准；maxSlice 77ms 未定位。

## 隔离与可用语言子集

核心仅接收字节数据、profile 与显式上下文，不 import Node、DOM、Vela。Node 用于构建/测试；系统音频/文件 API 仅在适配层。构建语法转换不能补齐缺失的运行时 API。

使用 ArrayBuffer、Uint8Array、Int16Array、Uint32Array、DataView、Math.imul、字节序和有符号运算时须验证具体行为。BigInt、Promise、TextEncoder/TextDecoder 不默认成为核心依赖；新引入的内建操作先核验目标能力。随机状态遵从 C Oracle，不以 Math.random 代替。

语言数据profile必须显式选择：`en-us`仍是partial-M12 JS路径；`cmn`完成C数据/差分候选和`CalcPitches_Tone`函数级切片，`jsRuntimeStatus=unsupported`。不得把cmn数据包中的Oracle WAV可播放或tone函数切片解释为QuickJS中文合成可用。

## 数据装载契约

`.txt` 是包装扩展名，内容保持上游原始字节。Node与设备当前候选均先采用全读驻留；D1已确认该候选同时保留898009B。分块组装为可用备选，完整reader及最终数据集的初始化/内存预算仍需重新测量。

- 全读驻留与分块组装具有相同最终驻留需求，后者只缓解单次 I/O 限制；必须记录组装临时块的峰值。
- 一次切片成功不能证明按需分页已可用。启用分页前定义页/缓存上限、跨页读取、缺页暂停与恢复、借用缓冲寿命、取消和迟到回调；与驻留模式进行差分。
- I/O、hash、组装、总初始化耗时分开；明确数据字节数、同时存活缓冲和可测 heap。缺少 heap API 时记录“不可测”，保守分配探针不测 OOM 边界，不代表峰值。

## 核心 PCM 分片与文件消费契约

核心输出分片 PCM；设备在完整 WAV 可用后播放。两者分别验收，不把文件播放包装成硬件 PCM streaming。

传给 Vela writeArrayBuffer 的 Uint8Array 必须满足 byteOffset=0 且 byteLength=buffer.byteLength；局部视图先复制到精确长度缓冲，末块和44字节头同样处理。0.4.0失败长度支持桥接丢失视图长度的解释，具体原生实现尚未证实。适配层明确 copy/retain 的缓冲所有权；retained 缓冲确认归还前禁止复用。使用有界队列，满则暂停生成，消费后恢复。每次 render 有有限工作预算，主动让出事件循环。取消使用会话代号隔离迟到回调，停止后释放队列、独占临时文件与音频资源。

M11 核心契约：command source 必须逐条产出命令并报告单调的 `inputBytes`、`codePoints`、`clauses` 进度；运行时强制默认上限 65536B、16384 code points、256 clauses、100000命令。`onAudio` chunk 的所有权交给消费者，必须调用 `release()`；池耗尽为显式 backpressure，未全部释放前拒绝新会话。完成/取消会调用 source `cancel()` 并清空命令窗口。

合成完成、文件完成与播放完成是三个事件。不同 chunk 大小拼接输出须一致；取消后新会话不得继承旧随机/滤波/音素状态。

A1 已验证被测短 WAV 的 append、非零 position 和头回填；采用有上限的 PCM 分块落盘、最终头回填、文件完成后播放。每次写使用精确 backing buffer，完整缓冲整写也保留；当前无需双临时文件封装。存储不足或超限显式报错，不静默截断。长文本按上游 clause 边界消费输入，并验证跨 clause 状态；有限文件队列播放/删除，不预生成全部音频。

22050Hz 直接播放失败且确认需要转换时，转换仅在适配层；单独测试重采样状态和跨块一致性，不改变核心差分采样率，不只改 WAV 头。

PCM 有界不代表总内存有界。输入文本、code points、clause、音素、WavePlan、数据缓存、待写 PCM、待播文件均需容量与超限策略。Node 与设备可采用不同的容量 profile，但容量内的行为不得不同。

## 设备验证纪律

探针手动启动、任务有界、支持停止和页面销毁。逐项记录 PASS/FAIL/UNSUPPORTED，系统事件成功不等于实际出声；用户听感与构建身份同时留痕。不能把 API 拒绝未经排查归咎于签名。

S1 从 M11 持续执行，M14 后对最终构建复验：至少 1 秒/30 秒生成样本、100 次短句会话、30 分钟有界运行、慢消费者、取消重启、前后台和文件失败/清理。长任务先在 Node/mock 验证；设备测试在已验证上限内手动启动，不自动探测 OOM/存储耗尽。若设备只支持较短输入，明确验证拒绝路径，不能声称支持完整 30 秒单文件。
