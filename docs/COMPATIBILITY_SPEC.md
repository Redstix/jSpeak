# Compatibility contract — draft v1

## 范围

目标是固定 eSpeak NG commit、固定编译配置和数据集下的行为兼容，不是跟踪浮动的“最新版”。首个 commit 已锁定为 `ba90c8e9f440ad544f674a790bb5f53878b6ffc5`，配置见 `upstream.json`。目前只有 CLI smoke reference，尚不是正式内部兼容基线。

首发 profile：纯文本、en-us、语速 175、音高 50、音量 100、显式 UTF-8，CLI 随机源设为 deterministic；参考输出是单声道 PCM16，采样率由 WAV 解析并逐例记录。2026-10-05 核验当前固定构建的 WAV 与 `phondata` 头均为 **22050Hz**，核心保持此采样率。16000Hz 设备双音探针不是参考合成规范；必要的设备重采样在适配层另行定义和测试，不改核心差分边界。

SSML、其他 voice、其他合成后端暂不支持，不得静默启用或替换。中文/其他语言保留为 M15，明确延期到单语言首发之后，不因实施英文而标记 M15 完成。未来启用前可试听上游中文评估产品价值；en-us 对非拉丁输入的既有行为仍属于当前 profile 的验证范围。

## 比较边界

| 边界 | 策略 |
|---|---|
| 输入解码、分类、分词 | 同输入模式下 code point、边界、分类 exact |
| 词典/规则选择 | 规则 ID、分支、标记 exact |
| 音素 | 同一处理阶段的数字 ID、所属表、重音、词边界 exact |
| VM | opcode、条件结果、状态变更、事件顺序 exact |
| 韵律/合成命令 | 整数/枚举 exact；单位、位宽须标明 |
| PCM | 默认 exact；非 exact 必须经审查的命名例外及具体数值阈值 |
| 听感 | 人工回归是补充，不替代前述判定 |

容差暂未批准，因此不允许用随意阈值放行。长度不同必须显式报告；默认不自动对齐、裁剪静音或忽略首尾。空输入、全静音、不同采样率、NaN/Infinity 都应有明确处理。

## Oracle 完整性

每个结果记录 upstream commit、编译器/配置、数据 SHA256、voice 参数、输入模式、随机源/初始状态、schema 版本。保留未插桩的参考构建，验证插桩前后可观测结果相同。重复生成必须先证明 C 自身的稳定性。

上游源码保持固定；插桩补丁独立管理。开发期 C 工具不进入设备运行时。没有 JS 对应实现时只声明 harness 自检通过，不声明差分兼容通过。

## 数字语义

按上游实际类型规定截断、取整、位移、乘法及溢出。不能默认 `a*b|0` 对任意宽度整数都等价。随机序列必须可控；不能把 Math.random 当成兼容噪声源。遇到 C 未定义/平台相关行为，记录参考平台与处理决策，不臆造跨平台等价。

## 阶段依赖

原始 M00–M16 编号保留作工作项，不作为严格单向调用链。音素表基础设施按需前移。M07 的 startSample/duration 在音素 mutation 完成前不得视作最终时序；M07/M08/M09 的调用与状态边界必须用固定源码确认。

具体执行顺序与原始设计修订见 [最终实施计划](DEVELOPMENT_PLAN.md)：M06 后先验证 M08 VM，再做 M07 集成及 M09/M10。M11 仍为有界运行时，M12 为 Vela 适配；文件播放不取消核心 PCM 分片、背压和有界内存的要求。D1 数据 manifest、A1 音频文件验证、P1 性能观察及 S1 稳定性是新增工作项，不占用原 M 编号。

跨阶段依赖允许建立真实的最小切片，不允许以 stub 通过验收。每项验收必须可在当前阶段执行；依赖未来 PCM 才能判定的工作标记为未完成。

## 发布

锁定上游后核查代码、数据、音频资源许可证及分发义务。纯 JS 移植不自动免除许可义务。发布前必须有第三方清单、对应源码/许可证方案及数据依赖闭包清单。
